## 評価して欲しいポイント

- Vuetify を活用し、開発側の負荷を抑えながら色・サイズ・UI/UX が統一されたデザインを実現した
- マークダウンで見やすい記事 UI を作成した
- 他人のプロフィールから、その人がいいねした記事を見られるようにした（透明性の向上）
- 最小限の構成を目指し、機能ごとにスクラム開発で進めた
- 記事を Markdown で書けるようにした
- コメント／質問で絞り込みができる機能を追加した
- 新規記事作成画面に、いろいろな装飾を選択できるマークダウンツールバーを実装した
- コードブロックを色付きでプレビュー表示できる／記事詳細でも色付きで表示される
- プロフィール画面でユーザーアイコンを変更できる機能を実装した
- プロフィール画面が多機能で、その人の興味・活動内容がまとめて見られる
- マークダウンを書く際に Ctrl+B（太字）などのショートカットコマンドが使える
- 箇条書きで改行したときに、そのまま箇条書きが継続される（ライブラリの恩恵）
- 他チームよりきれいな Pull Request を出せている
- 他チームよりスクラム開発としての思想を持って開発できた
- ORM（O/R マッパー）を使わず、生 SQL を書いて実装した
- GitHub の issue / PR 番号が 300 番台まで到達するほど、活発に運用した
- チーム内で設計について積極的に共有・議論しながら進めた

## 苦労したポイント

- Git のコンフリクト対応が大変だった
- AI（Copilot / ChatGPT 等）の使い方が難しかった
  - ハルシネーションを起こさせず、どこまで稼働させるかの線引き
  - AI がやっていることを理解しきれず、深掘り・議論するのが難しかった（質問力不足）
  - ChatGPT のようなチャットアプリで、どこまでコンテキストを読み込ませるかの判断
  - 分からないことをネットで調べても理解できず AI に頼る／逆にネット検索すべき場面の見極めが難しかった
  - 自分のなかで「どこまで知識として持っておくか」「質問力」「ネット検索力」のバランスを取るのが難しかった
- タスク管理が難しかった
  - タスク同士の依存関係があり、並列で進められない場面があった
  - 優先順位が正しいかを確認しながら進めるのが大変だった
- バックエンドの知識が乏しく、バックエンドを触るのがかなり大変だった
- バックエンドの知識不足によって、スクラム開発として透明性を持って進めるのが難しかった
- 初期は GitHub の issue / PR の運用に慣れていなかった
- チームに知識がない時期は、専門用語を使わずに説明する必要があり大変だった
- コードレビューの仕方が分からず、レビューが難しかった
- Copilot のレビュー対応が難しかった（何を言っているか分からない／知識不足で対応方針が立てづらい）
- 開発環境（Windows）まわりの苦労
  - Windows がバグったり、ラグが重かったりした
  - 拡張機能の導入が面倒だった
  - 動作が遅かった
  - ホームディレクトリ（ユーザー名）が日本語のせいで導入できないツールがあり、Linux 導入も大変だった
- 初期の頃の PR に動作確認の記載がなく、他人が見やすい／確認しやすい PR になっていなかった
- issue の立て方が最初は雑で、何をすべきかが分かりにくかった／issue の内容を理解するのも難しかった
- GitHub Education の Copilot 課金プランを使えると思っていたが、申請タイミング（4/23）の直前（4/22）で新規登録者は使えなくなっており、当てが外れた
- チーム内での知識共有が難しかった
- 休み時間も働いてしまい、結果的に長時間作業で生産性が下がっていた。きちんと休んで生産性を上げる工夫をすべきだった
