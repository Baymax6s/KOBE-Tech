# 07. 夜も眠れなくなるような問題は何だろう

> 状態: 確定（緩和策はたたき台）

中核（[01](01_why.md)）が**社会的な仕掛け**であることが、最大のリスク源。
透明化もモチベも「他の学生が投稿している」が前提なので、人と投稿が無いと中核ごと成立しない。

## 筆頭リスク: コールドスタート / 過疎

最初に投稿が集まらず、透明化するものが無く、モチベの燃料がゼロになる。コミュニティ系プロダクトの代表的な死因。

緩和策（たたき台）:
- 立ち上げ時にチーム自身がシードとなる投稿・回答を入れ、空っぽに見せない（既に seed マイグレーションあり）
- 最初の対象を絞る（特定のクラス・学年から始め、密度を作る）
- 「最初の数件」を投げやすくする導線（後述の心理的ハードル対策と一体）

## リスク2: 投稿の心理的ハードル

初学者が「稚拙な質問・記事を晒すのが怖い」。透明化（見える）が、逆に投稿を抑制しうる。中核と裏腹の関係。

緩和策（たたき台）:
- 「わからないことは置いていける」を歓迎する空気・コピー（[03](03_package-design.md)）
- 質問のテンプレートや最小入力で投稿できるUX
- ネガティブ評価（低評価ボタン等）を持たない設計

## 割り切り（リスクとして扱わないと決めたこと）

混同しやすいので、あえて「リスクにしない」と明記しておく。

- **学内限定の担保**: サインアップ機能が無く、ログインできるのはシードしたユーザーだけ（[05](05_neighbors.md)）。
  外部から勝手にアカウントが増えないため、「学内限定」は仕組みで成立済み。流入リスクとして監視する必要はない。
- **期間後の持続性 / 本番運用**: 本プロジェクトは本番デプロイを完遂する想定ではない。
  Render の無料枠に載せているが同時アクセス可能数はごく少なく、将来的な継続運用も計画しない。
  よって「期間後に止まる」ことは失敗ではなく前提。スケールや恒久運用に時間を割かない（[09](09_tradeoffs.md) の配分と整合）。
