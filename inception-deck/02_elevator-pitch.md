# 02. エレベーターピッチ

> 状態: 確定（課題側で指定）

## ピッチ本文

- **IT分野学生の技術力不足を解消したい**
- **神戸電子IT分野学生**向けの、
- **プログラミング情報共有サイト**というプロダクトは、
- **学生間での技術の情報共有や、自身の創作物を公開できるサイト**です。
- これは、**プログラミングでわからないことを解決できたり、自身の制作物を公開すること**ができ、
- **Qiita や Stack Overflow** とは違って、
- **参加している学生同士の活動が透明化されることでモチベーションを保ちやすい**、という特徴が備わっている。

## テンプレート対応

| 項目 | 内容 |
|------|------|
| 1. 解決したい課題 | IT分野学生の技術力不足（＝学習が続かないこと） |
| 2. 対象顧客 | 神戸電子IT分野学生（閉じた学内コミュニティ。[05](05_neighbors.md)） |
| 3. プロダクト名 | プログラミング情報共有サイト（仮） |
| 4. カテゴリー | 学内向けプログラミング情報共有サイト |
| 6. 代替手段の最右翼 | Qiita / Stack Overflow |
| 7. 決定的な差別化 | 学生同士の活動の透明化によるモチベーション維持 |

## 補足: 差別化を成立させる前提

Qiita / Stack Overflow は「不特定多数の知識ベース」。本プロダクトは「**顔の見える学内の仲間**」であることが価値の源泉。
透明化（[03](03_package-design.md)）とモチベーションは、相手が**同じ学校の知っている仲間**だからこそ効く。
この前提が崩れる（誰でも入れる匿名の場になる）と、差別化も崩れる。境界の扱いは [05](05_neighbors.md) を参照。
