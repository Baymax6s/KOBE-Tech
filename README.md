# KOBE-Tech

神戸電子専門学校 ソフト4の1回目のチーム制作で作成する Web アプリケーションのリポジトリです。

スクラム開発で、プロダクトバックログアイテム（PBI）をもとに機能を実装していきます。

## プロダクト概要

学生や教員が記事・質問・回答・制作物を投稿し、知識共有やフィードバックを行えるサービスを目指します。

主な利用者は以下を想定しています。

- 学生
- 教員
- 管理者
- 未ログインの閲覧者

## プロダクトバックログアイテム（PBI）

| No. | ユーザーストーリー |
| --- | --- |
| 1 | 閲覧者として投稿された記事の詳細な内容を参照したい。自分が知りたい情報があるか確認したいからだ。 |
| 2 | 回答者として投稿された質問に回答したい。自分の知識を他の学生に役立てたいからだ。 |
| 3 | 質問者として分からないことを質問でき、多くの人が見てくれる場所がほしい。たくさんの人から答えが欲しいからだ。 |
| 4 | 閲覧者として投稿された最新の記事を一覧で見たい。新しくどんな記事が投稿されているかを知りたいからだ。 |
| 5 | 閲覧者として記事に対してコメントを書きたい。記事の内容について質問や指摘をしたいからだ。 |
| 6 | 投稿者として自分の書いた記事への評価を知りたい。自分の記事の正確さや他者にわかりやすく伝わっているかを知って参考にしたいからだ。 |
| 7 | 閲覧者として分類別に記事や質問を閲覧したい。興味のある記事を簡単に探したいからだ。 |
| 8 | 閲覧者・質問者として優れた回答に対して高い評価をしたい。利用者全体に回答の価値を知らせたいからだ。 |
| 9 | 閲覧者として投稿者や回答者のプロフィールを知りたい。質問や回答の背景を知りたいからだ。 |
| 10 | 管理者としてユーザー（学生、教員）にパスワードを変更させたい。セキュリティを高めたいからだ。 |
| 11 | 投稿者として自分の制作物を公開できるようにしたい。自分の制作物に対して閲覧者の評価やアドバイスがほしいからだ。 |
| 12 | ユーザー（学生、教員）としてログイン・ログアウトしたい。Web サイトの機能を利用したいからだ。 |

## デモデータとログインアカウント

セットアップ（マイグレーション + seed 投入）が済むと、デモ用のユーザー・記事・コメント・いいねが入った状態でアプリを触れます。記事・質問・回答・プロフィールが取りうる「ほぼ全部の状態」を一通り見られるように作ってあります。

### ログインアカウント

ログインは **ユーザー名 + パスワード** で行います（表示名がそのままログイン名です）。**デモユーザーのパスワードは全員 `Password`** です。

| ユーザー名 | 役割・人物像 | プロフィールの状態 |
| --- | --- | --- |
| `admin` | 管理者。記事も多くベストアンサーも複数持つ | アバターあり / 自己紹介あり |
| `鈴木健一` | 講師。回答が手厚く、ベストアンサーを獲得している | アバターあり / 自己紹介あり |
| `高橋美咲` | フロントエンド志望の学生。記事＋ベストアンサーあり | アバターあり / 自己紹介あり |
| `渡辺翔太` | サーバーサイド志望の学生。制作物（個人開発）を投稿 | アバターあり / 自己紹介あり |
| `田中太郎` `山田花子` `佐藤次郎` | 一般的な投稿・コメント利用者 | アバターあり / 自己紹介あり |
| `伊藤さくら` `中村大輔` | アバター未設定のユーザー（既定アイコン表示） | アバターなし / 自己紹介あり |
| `小林優子` | 投稿はせず「いいね」だけする閲覧者 | プロフィール未作成の最小状態 |

> まず触るなら `admin` か `鈴木健一` がおすすめです。記事・回答・ベストアンサー・プロフィールが充実していて、ログイン後の機能をひと通り確認できます。閲覧者目線を見たいときは `小林優子` でログインすると「投稿ゼロ・いいねのみ」の最小状態が確認できます。

### 機能ごとの見どころ（どこを見ればいいか）

| 見たい機能・状態 | 見に行く先 |
| --- | --- |
| 記事一覧・新着順 | トップの記事一覧。最新記事は **「Postmanで始めるAPIデバッグ入門」**（いいね・コメントともにゼロの投稿直後の状態） |
| Markdown の描画（見出し・表・コード・引用） | **「Markdown 記法チートシート」** / **「Gitのrebaseとmergeを使い分ける」** |
| タグでの絞り込み | タグ多めの **「個人開発した蔵書管理アプリを公開します」**（4タグ）／ タグなしの **「プログラミング学習を続けるための小さな習慣」** |
| 学内特化タグでの絞り込み | 神戸電子のカリキュラム語彙 **`C言語課題36` / `C#課題24` / `Java課題11`**（汎用タグとの差別化。例: `/articles?tag=C言語課題36`） |
| いいねの多寡 | 人気記事の **「個人開発した蔵書管理アプリ」「Gitのrebaseとmergeを使い分ける」**（いいね多）／ いいねゼロの **「Postmanで始めるAPIデバッグ入門」** |
| コメントのネスト表示・折りたたみ | **「Gitのrebaseとmergeを使い分ける」** のコメント（最大4階層） |
| 質問 → ベストアンサー | **「Gitのrebaseとmergeを使い分ける」「TypeScriptの型で安全なAPIクライアントを作る」「Vue 3 + Vuetifyで学ぶフロントエンド開発」** |
| 回答にコードブロックが乗るベストアンサー | 学内課題記事 **「C言語課題36：ポインタのイメージを掴む」「Java課題11：継承とインターフェースの使い分け」**（回答者: `渡辺翔太`） |
| 回答はあるがベスト未選択の質問 | **「個人開発した蔵書管理アプリ」** 内の「書影の取得にはどの API を…」 |
| 未回答の質問 | **「CSS Grid と Flexbox の使い分けメモ」** 内の質問 |
| 制作物（個人開発）の公開 | **「個人開発した蔵書管理アプリを公開します」**（投稿者: 渡辺翔太） |
| プロフィール（アバター・自己紹介・ベストアンサー数） | `鈴木健一` / `admin`（充実）、`伊藤さくら`（既定アイコン）、`小林優子`（最小状態） |

> seed は `api/migrations/` 配下のマイグレーションとして管理しています。投入される内容を変えたいときはマイグレーションを追加してください。

## 開発方針

- スクラム開発で進める
- PBI をもとにスプリントごとの実装対象を決める
- 実装前に目的と受け入れ条件を確認する
- API 変更時は OpenAPI 定義と TypeScript クライアントを更新する
- 小さく動く単位で実装し、レビューしやすい変更にする

## 現在の主な機能

- ログイン
- ログアウト
- 記事一覧表示
- 記事投稿
- 認証中ユーザー情報取得

## API 型生成

バックエンドの OpenAPI 定義を更新した場合は、フロントエンド側の API 型を再生成します。

```bash
cd app
npm run generate:api
```
