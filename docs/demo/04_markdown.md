# 柱4: 書きやすさ＝Markdown

## ひとこと（説明スライドで言うこと）

「記事も回答も **Markdown** で書ける。見出し・表・引用・そして**コードブロック**（シンタックスハイライト付き）。Markdown は **GitHub で使われている世界標準の記法**（GitHub は全世界 約1.8億ユーザー）。つまり**一度覚えれば一生使える書き方**で、コードを綺麗に共有できる＝『書きやすいから投稿が続く・質が上がる』。」

## 操作（20〜40秒・録画推奨）

1. **記事側**: 「Markdown 記法チートシート」または「C言語課題36：ポインタのイメージを掴む」を開き、見出し・表・**コードブロック**が綺麗に描画される様子を見せる（コードのコピーボタンも一瞬）
2. **回答側（差別化の押し）**: 「C言語課題36」記事のリプライ欄で、**渡辺翔太の回答に C のコードブロックが綺麗に乗っている**ことを見せる
   - 「記事だけでなく**回答にもコードが綺麗に乗る**」と言うと効く
3. （任意）`/articles/new` を開いて、左に書いた Markdown が右でプレビューされるエディタ（md-editor-v3）を一瞬見せる

## 前提（重要）

- 回答のコード描画は `feature/302` が必要。録画環境に取り込んであることを確認（[README](README.md) の「事前準備」）

## 見せどころ

- 「GitHub標準＝1.8億ユーザーの記法」という**規模感の数字**を一度だけ口に出すと説得力が出る
- コードが**ベタ打ちでなくハイライトされて**いることを画面で見せる
