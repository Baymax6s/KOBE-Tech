# 通しデモ: 命題が1本につながる山場（1.5〜2分）

4本柱の機能が、**1人の学生の体験**としてつながる瞬間を見せる。
「学内タグで探す → コードで回答 → ベストアンサー → プロフィールに貢献が積み上がる」を一気通貫で。

## 役者とデータ

- **質問者**: `中村大輔`（初心者・id 9）… この人がベストアンサーを「選ぶ」
- **先輩**: `渡辺翔太`（id 7）… コードで回答済み。ベスト獲得2件 → このデモで**3件**に
- 舞台: 「**C#課題24：例外処理でよくある詰まり**」（回答は2件あり、まだ**ベスト未選択**）

> このデモは状態を変える（ベストを選ぶ）。**録り直すときは `cd api && docker compose down -v && docker compose up -d` でリセット**。

## 操作手順

1. **探す（柱3）**: 未ログイン or `中村大輔` で `/articles` → タグ **`C#課題24`** で絞り込み（`/articles?tag=C#課題24`）
2. 記事「C#課題24：例外処理でよくある詰まり」を開く
3. **読む（柱4）**: リプライ欄へ。中村の質問と、2件の回答（鈴木のテキスト回答 / **渡辺のコードブロック回答**）を見せる
4. **貢献を可視化する（柱2）**: `中村大輔`（質問者本人）でログインしている状態で、**渡辺のコード回答**の「**ベストアンサーに選ぶ**」を押す → 👑 が付く
5. **透明化で締める（柱1）**: 渡辺翔太のプロフィール **`/profile/7`** へ移動 → **ベストアンサー獲得が3件に増えている**／獲得記事一覧にこのC#記事が並ぶ

## 締めのナレーション（命題に戻す）

「いま見たのは、**学内の課題でつまずいた後輩**を、**顔の見える先輩**が助け、その**貢献がプロフィールに積み上がる**流れです。こうして**仲間の活動が見える**から、教える側も学ぶ側も**モチベが続く**。学習が続くから、**技術力が上がる**。これが私たちの作りたかったものです。」

## 失敗時の保険

- ライブでやるなら、ベスト選択が滑ったとき用に**この手順の録画も用意**しておく（README の「事前準備」でリセットしてから録る）
