## なぜ作るのか —— 私たちの仮説

> **プロフィール（＝活動の透明化）**
> → 仲間の活動が見える
> → **モチベが続く**
> → 学習が続く
> → **技術力が上がる**

「情報共有サイト」が技術力を上げるのではない。**学習が続くこと**こそが本質。

#### Qiita / Stack Overflow との違い

不特定多数の知識ベースではなく、**顔の見える学内の仲間**。
だから「あの先輩が答えてくれた」がモチベになる。

## 製品の4本柱

1. **活動の透明化** —— プロフィール
2. **貢献の可視化** —— 質問 → 回答 → ベストアンサー
3. **学内に最適化された分類** —— 自由タグ
4. **書きやすさ** —— Markdown

この順で、各機能が命題の因果に沿ってつながっていく。

## 柱1：活動の透明化 —— プロフィール

- アバター・自己紹介に加え、**投稿記事・いいね・ベストアンサー獲得**が一覧に
- プロフィールが、その人の**活動の通信簿**になる

→ 「**仲間の活動が見える**」の本体。透明化のスタート地点。

## 柱2：貢献の可視化 —— ベストアンサー

- 質問に仲間が回答し、質問者が**ベストアンサー**を選ぶ
- 「どの回答が一番役に立ったか」が可視化され、**貢献が記録に残る**

→ 質問機能そのものは珍しくない。**ベスト＋顔の見える仲間＋プロフィールへの蓄積**がセットで効く。

## 柱3：学内に最適化された分類 —— タグ

- タグで記事を分類・絞り込み
- 語彙が**神戸電子のカリキュラムに最適化**：**`C言語課題36` `C#課題24` `Java課題11`**

→ Qiita / Zen の汎用タグでは届かない「今やってる**あの課題**」にまっすぐ辿り着ける。

## 柱4：書きやすさ —— Markdown

- 記事も回答も Markdown：見出し・表・引用・**コードブロック**（ハイライト付き）
- Markdown は **GitHub の世界標準の記法**（GitHub は全世界 **約1.8億ユーザー**）

→ 一度覚えれば一生使える書き方で、**コードを綺麗に共有**できる。

## 通しデモ：4本柱が1本の体験になる

**学内の課題でつまずいた後輩を、顔の見える先輩が助ける**

1. 「**C#課題24**」タグで探す　（柱3）
2. 質問に、先輩が**コードブロック**で回答　（柱4）
3. 質問者が**ベストアンサー**に選ぶ　（柱2）
4. 先輩のプロフィールに**貢献が積み上がる**　（柱1）

→ 仲間の活動が見えるから、**教える側も学ぶ側もモチベが続く**。

## 作業プロセス：スプリントの回し方

```text
マイルストーン(PBI)
   → スプリントプランニング
      → 実装 ＋ PR レビュー
         → スプリントレビュー（デモ）
            → ふりかえり（KPT）
               → 次のスプリントへ ↺
```

GitHub の**マイルストーンに Issue を紐づけて**、1週間（Sprint2 のみ2週間）単位で反復。

<!-- プロセスは簡単に。図1枚でリズムを見せる。〜40秒。 -->

## ベロシティの推移と考察

<div class="bar">

```text
S1 (1週)  ███████████████████              19
S2 (2週)  ██████████████░░░░░░░░░░░         14 (+11 授業外) = 25
S3 (1週)  ███████████████████              19
S4 (1週)  █████████████████████            21  ← 過去最高
```

</div>

<span class="small">█ 期間内 / ░ 授業外で踏ん張った分。見積もりはチームベース。</span>

- **S2 の谷**：チーム内で風邪が流行し欠席続出。Git のコミット数も S1 比で約3割減。
- **授業外で +11 を消化**して踏ん張り、**S3 で通常復帰・S4 で最高値**へ。

→ 外乱を越える**回復力**と、チームの**成熟**。

<!-- 正直に谷を見せてからの回復が一番効く。数値の精度より物語。 -->

## スプリントごとのチームの成長

| Sprint | 協働の変化 |
| --- | --- |
| **S1** | Issue → PR → レビューの**開発フローに乗り始めた**（型の習得） |
| **S2** | 良いレビューをもらう**PRの出し方・Issueの書き方を工夫**（伝える力） |
| **S3** | 経験者の牽引型から、**全員が相互に教え合う構造へ**（自己組織化の芽） |
| **S4** | 相互学習が定着し**過去最高速**（自走するチームへ） |

→ 「フローを覚える → 伝え方を磨く → 知識が分散する → 自走する」
